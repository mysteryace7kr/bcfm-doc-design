# 인쇄문서 디자인 시스템

## 0. 쪽 나눔은 네가 하지 않는다

**이 절이 이 스킬에서 가장 중요하다.** 원고를 붓는 것은 네 일이고,
**쪽을 어디서 나눌지는 `fit.sh` 가 정한다.** 순서를 지키면 채움률이 저절로 맞는다.

절대 하지 않는다.

- **제목마다 쪽을 새로 시작하지 않는다.** `1.` `2.` `3.` 이 새 쪽에서 시작해야 할
  이유는 없다. 앞 쪽이 덜 찼으면 제목은 그 쪽 중간에서 시작한다.
- **「이어서」·「(계속)」 같은 제목을 만들지 않는다.** 쪽이 넘어가면 그냥 넘어간
  것이다. 표시하지 않는다.
- **쪽을 일부러 비우지 않는다.** 사용자가 특별히 요청하지 않는 한, 한 쪽은
  채우고 다음으로 넘어간다.
- **눈대중으로 `<section class="page">` 를 나누지 않는다.** 몇 줄이 들어가는지
  세어서 맞출 수 없다. 재보지 않고 나눈 쪽은 예외 없이 헐겁게 나온다.

## 1. 아키타입 고르기

문서 종류가 아니라 **레이아웃 형태**로 고른다.

| 컴포넌트 | 쓸 때 |
|---|---|
| `report.dc.html` | 여러 쪽, `○▶※⇨` 개조식 위계 + 요약밴드 + 번호 섹션 — 보고서·검토·개념설명·언론분석 |
| `formal.dc.html` | 수신처·발신명의가 필요한 문서 — 기안(공문)·건의서·질의서·신청서. 결재란 포함 |
| `brief.dc.html` | 1~2쪽, 타임라인·항목 나열 — 업무진행사항·요약보고 |

애매하면 `report`.

## 2. 만들기

1. `components/` 에서 해당 `.dc.html` 을 복사한다.
2. **본문 텍스트만 교체한다.** `<helmet>` 안 `:root`·클래스 정의는 건드리지 않는다.
3. 불릿은 클래스로 찍는다 — `.o`(○) `.k`(가.나.다.) `.t`(▶) `.n`(※) `.r`(⇨) `.lead`(번호 문단).
4. 표는 라벨 열을 `<th>` 로, 수치 셀만 `class="num"` 으로 우측정렬한다.
5. `slot="footer"` 가 아니라 각 `section.page` 안 `.foot` 의 문서명을 바꾼다.
   쪽 번호 `n / N` 은 그대로 둔다 — `fit.sh` 가 채운다.
6. **원고 전체를 `<section class="page">` 하나에 다 붓는다.** 쪽을 나누지 않는다.
   한 쪽을 아무리 넘겨도 그대로 둔다. 다음 단계가 나눈다.
7. **`fit.sh` 를 돌린다.**

```bash
~/.claude/skills/doc-design/sync/fit.sh 내문서.dc.html
```

이게 하는 일 — 블록 하나하나의 실제 높이를 헤드리스 크롬으로 재서,
**한 쪽이 허용하는 데까지 눌러 담고 넘칠 때만 다음 쪽으로 넘긴다.**
쪽 경계에 걸린 **문단·표·인용은 나눠서** 채운다. 쪽 번호 `n / N` 도 다시 매긴다.
마지막 쪽이 헐거우면 속성 패널 범위 안에서 본문크기·줄간까지 같이 맞춰 본다
(같은 쪽수라면 **큰 글자**를 고른다). 원본은 `.bak` 로 남는다.

쪼갤 때 지키는 것 — 낱말 가운데를 자르지 않고, 앞뒤로 두 줄씩은 남기며, 표는 행
단위로 나누고 이어지는 쪽에 머리행을 다시 얹는다. **글자는 한 자도 늘거나 줄지
않는다**(합쳐서 원본과 대조하고, 어긋나면 파일을 쓰지 않고 멈춘다).

```
■ 내문서.dc.html  → 재배치 — A4 6쪽  ·  본문 13px / 줄간 2
  쪽        채움률      남은 여백   판정
  1      99.1%        2mm   적정
  ...
  평균 94.9%
```

`--dry` 는 고치지 않고 결과만 본다. `--no-sweep` 은 본문크기·줄간을 건드리지 말라는
뜻이고, `--no-split` 은 블록을 나누지 말라는 뜻이다.

8. 확인이 필요하면 PDF 로 뽑아 본다. `fit.sh` 와 같은 조건에서 렌더하므로
   **쪽수가 보고된 것과 같아야 한다.**

```bash
~/.claude/skills/doc-design/sync/topdf.sh 내문서.dc.html
```

### 반드시 새 쪽에서 시작해야 할 때만

사용자가 "이 절은 새 쪽에서 시작해줘" 라고 **명시적으로 요청한** 블록에만
`data-break="page"` 를 붙인다. `fit.sh` 가 그 앞에서 쪽을 끊는다.
요청받지 않았으면 붙이지 않는다.

```html
<h2 data-break="page">5. 별첨</h2>
```

## 3. 하지 말 것

- `@page` 규칙 직접 작성 — `doc-page.js` 가 소유한다
- 푸터를 `slot="footer"` 로 옮기기 — `section.page` 와 혼용이 금지되어 있고, 옮기면 쪽 번호를 쓸 수 없다. 푸터는 각 `section.page` 안에 직접 넣는다
- `<doc-page>` 의 `size="a4"` 를 지우거나 바꾸기 — 이 값이 **화면 카드 크기와 인쇄 용지를 동시에** 정한다
- `<style>` 맨 위의 `@property --body-fs` / `--body-lh` 블록 삭제 — 속성 패널 값이 전달되지 않는 경로에서 본문이 16px·줄간 normal 로 튀는 것을 막는다
- 본문크기·줄간을 손으로 고치기 — 네 군데(`@property` 둘, 문서 끝 `data-props` 기본값, `renderVals` 의 `?? 14`)를 함께 고쳐야 하고, 하나만 놓치면 Claude Design 이 옛 값으로 되돌려 쪽 나눔이 어긋난다. `fit.sh` 가 네 군데를 함께 고친다
- 링크 외 유채색 추가
- `▢` 사용 — 글리프가 없어 `□` 로 폴백된다
- `position:fixed`·뷰포트 단위(`vh`/`vw`) — 인쇄에서 깨진다
- 색·크기 값을 인라인으로 새로 쓰기 — `var(--토큰)` 을 쓴다

## 5. 합격 기준

`fit.sh` 는 마지막에 **합격 / 불합격**을 찍는다. 이게 이 시스템의 기준이다.

| 항목 | 기준 | 왜 |
|---|---|---|
| 잘린 쪽 | **0** | 내용이 사라진다 |
| 마지막 쪽을 뺀 모든 쪽 | **채움률 92% 이상** | 헐거운 쪽을 남기지 않는다 |
| 마지막 쪽 | **기준 없음** | 꼬리는 남는 내용만큼만 찬다. 메우려고 말을 지어내지 않는다 |
| 본문 크기 | **13px 이상** | 인쇄해서 사람이 읽는다 |
| 본문 글자 | **그대로** | 조판이 내용을 바꾸면 안 된다 |

**합격이면 그대로 낸다.** 눈으로 다시 맞추지 않는다.

**불합격이면 도구가 더 할 수 있는 게 없다는 뜻이다.** 까닭별로 할 일이 다르다.

| 불합격 사유 | 할 일 |
|---|---|
| 넘쳐서 잘린다 | 한 블록이 한 쪽보다 크다. 그 표를 둘로 나누거나 원고를 쪼갠다 |
| 92% 못 채운 쪽이 있다 | 그 자리에 나눌 수 없는 표·제목 덩어리가 걸렸다. **그 쪽만 사람이 본다** |
| 본문이 13px 미만 | 원고가 길다. 줄이거나 쪽수를 늘린다 — 글자를 더 줄이지 않는다 |

기준을 못 지킨 채로 "그럴듯해 보인다"고 넘기지 않는다. 그렇게 넘긴 문서가
8쪽 평균 74% 로 나왔다.

## 4. 산출

Claude Design 에 등록해 편집·PDF 내보내기로 쓴다.

### 화면 = PDF

`<section class="page">` 하나가 A4 한 쪽이다. **편집 화면에 한 쪽이 카드 하나로
보이고, 그대로 인쇄된다.** 화면 카드 수 = PDF 쪽수이며, 내보내기 용지를 무엇으로
고르든 쪽수와 구성은 변하지 않는다.

세는 말은 **"쪽"으로 통일한다** — "장"·"페이지"를 섞어 쓰지 않는다.
`<section class="page">` 하나 = 편집 화면 카드 하나 = PDF 한 쪽 = A4 용지 한 장이고,
넷이 항상 1:1이다.

### 채움률

한 쪽에 넘치면 다음 쪽으로 흐르지 않고 **잘린다**(`overflow:hidden`). 모자라면
그대로 빈 여백이 된다. 지면이 스스로 맞춰 주는 것은 없다.

**그래서 `fit.sh` 로 맞춘다.** 목표는 **95% 안팎**이고, 판정은 이렇다.

| 채움률 | 판정 |
|---|---|
| 100% 넘음 | 잘린다 |
| 92~100% | 적정 |
| 80~92% | 조금 빈다 |
| 80% 미만 | 비었다 |

마지막 쪽은 남는 내용만큼만 차므로 헐거울 수 있다. **그건 정상이다** —
내용이 5.2쪽어치면 6쪽째는 20%밖에 안 찬다. 그걸 메우려고 없는 말을 지어내지
않는다. 대신 `fit.sh` 가 본문크기·줄간을 조여 5쪽에 담을 수 있는지 먼저 본다.

**뼈대는 이 기준에서 뺀다.** `components/` 의 세 서식은 자리표시만 든 출발점이라
채우려고 가짜 항목을 넣을 이유가 없다. 기준은 원고를 부어 완성한 문서에 적용한다.

### 재기만 할 때

```bash
~/.claude/skills/doc-design/sync/measure.sh 내문서.dc.html
```

고치지 않고 쪽별 채움률만 본다. 한 쪽 용량은 `report`·`brief` 기본값(14px/1.85)에서
37.6줄, `formal` 기본값(13.5px/1.75)에서 41.2줄이다. 세부 수치는 `STYLE.md` 참조.

### 처음 한 번

`fit.sh`·`measure.sh` 는 측정용 Noto Sans KR TTF 를 쓴다. 없으면 이렇게 받는다.

```bash
~/.claude/skills/doc-design/sync/fontcache.sh
```

웹폰트를 네트워크에서 받게 두면 헤드리스 크롬에서 제때 안 앉아 **대체 글꼴로
재는 사고**가 난다. 같은 문장이 6% 좁게 잡혀 줄바꿈이 달라지고, 잰 채움률이
실제 인쇄와 어긋난다. 로컬 TTF 를 물려 막는다.

어법·종결어미·문서 골격은 `doc-style` 스킬이 담당한다.
