# 인쇄문서 디자인 시스템

검토한 Markdown 원고를 BCFM의 흑백 A4 서식에 옮길 때 사용한다.
서식·토큰 사양은 `STYLE.md`, 도구 절차는 `sync/README.md`를 참고한다.
어법·종결어미는 `doc-style`의 영역이다.

## 문서 만들기

1. `components/`의 report(기본 검토보고), formal(수신·결재 포함 공문),
   brief(업무진행 요약) 중 레이아웃에 맞는 서식을 복사한다.
2. 원고를 `<doc-page size="a4" margin="20mm">` 안에 순서대로 이어 쓴다.
   `section.page`를 만들거나 고정 쪽 모델과 혼용하지 않는다.
3. 불릿은 `.o`(○), `.k`(가.나.다.), `.t`(▶), `.n`(※), `.r`(⇨), `.lead`를 쓴다.
   표는 수치 셀에만 `num`을 쓰고 긴 표에는 `thead`를 둔다.
4. `slot="footer"`의 문서명·기관명을 바꾼다. 현 구현은 쪽 번호를 제공하지 않는다.
5. 기본 흑백·Noto Sans KR·글자 크기·줄간·기호 위계·토큰을 유지한다.
   `@property`와 `doc-page`의 글꼴 지정을 삭제하지 않는다.

## 줄바꿈과 쪽 나눔

- 템플릿의 `@page { size:A4 }`가 A4를 정한다. `size="a4"`만으로 인쇄 용지를
  보장하지 않는다. 여백은 런타임의 `margin`에만 두고 중복 추가하지 않는다.
- 제목과 뒤 내용을 붙이고, 표는 행 단위, 긴 인용문은 문단·줄 단위로 흐르게 한다.
  짧은 밴드·카드·결재·서명은 유지한다. 긴 카드에는 `allow-split`을 사용한다.
- `keep-all`은 단어 중간 분리를 줄이고 `anywhere`는 한 줄보다 긴 주소의 넘침을 막는다.
  `pretty`와 `widows/orphans`로 모든 한 단어·한 글자 고립이 해결된다고 설명하지 않는다.
- 의미상 붙일 짧은 날짜·금액 등에는 `keep-phrase`를 제한적으로 사용한다.
  전체 문장·긴 셀의 `nowrap`, 임의 `<br>`, 모든 표의 분할 금지는 쓰지 않는다.
- `break-before:page`는 사용자가 새 쪽 시작을 명시한 경우에만 쓴다.

## PDF 확인

```bash
~/.claude/skills/doc-design/sync/fontcache.sh
~/.claude/skills/doc-design/sync/topdf.sh 내문서.dc.html 결과.pdf
~/.claude/skills/doc-design/sync/checkpdf.sh 내문서.dc.html
```

`checkpdf.sh`는 기본 A4·20mm 서식의 **본문 잉크 도달률 참고값**이다.
92% 미만만으로 불합격 처리하거나 글자를 줄이지 않는다. 구버전 도구가 합격이라고
표시해도 원문·글꼴·잘림·고립 줄의 검증이 끝난 것은 아니다.
PDF의 모든 쪽을 열어 제목 고립·행 분할·마지막 짧은 줄·가로 넘침·글자 보존을 확인한다.
화면은 A4 폭의 긴 시트이므로 실제 쪽 경계는 PDF에서 확인한다.
브라우저 인쇄도 A4·100%·머리글/바닥글 해제를 확인한다.

확인용 도구는 로컬 TTF와 macOS Chrome을 쓴다. React CDN과 고정 대기 시간에
의존하므로 빈 PDF·대체 글꼴을 특히 확인한다. 파일 생성 성공만으로 완료하지 않는다.
Claude Design의 다른 TTF·렌더 경로까지 같다고 보장하지 않는다.

## 마지막 한 줄 때문에 쪽이 늘 때

1. 강제 줄바꿈, 큰 문단·제목 간격, 통째로 유지한 블록을 먼저 확인한다.
2. 간격을 소폭 조정한 후보를 원본과 실제 PDF로 비교한다.
3. 필요하면 속성 패널 범위에서 줄간·본문 크기를 조정하되 본문 13px 미만은 쓰지 않는다.
   코드로 조판값을 바꾸는 경우 `@property`, var 폴백, data-props 기본값,
   renderVals 기본값을 함께 맞춘다.
4. 원문과 가독성을 지키기 어려우면 다음 쪽을 허용한다. 내용을 삭제하거나 지어내지 않는다.

**흐름 문서에 `fit.sh`·`measure.sh`를 실행하지 않는다.** 두 도구는 이전
`section.page > .body` 문서 전용이다. 현재 흐름 서식의 자동 꼬리 보정기는 없다.
흐름 문서라도 한 쪽보다 큰 행·고정 높이·overflow 숨김은 별도 검증이 필요하다.
